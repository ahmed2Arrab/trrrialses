# التشغيل والإدارة

## المتطلبات

- تثبيت Node.js وnpm.
- مساحة تخزين محلية دائمة لمجلد `data/`.
- بناء الواجهة يتطلب تثبيت اعتماديات `frontend/`؛ الأمر الجذري `npm run build` ينفذ ذلك ثم يشغل TypeScript وVite.

راجع الإصدارات المتوافقة مع الاعتماديات في `package.json` و`frontend/package.json` عند تحديث Node.js.

## تشغيل الخادم محليًا

من جذر المستودع:

```powershell
npm install
$env:INITIAL_ADMIN_USERNAME = "admin"
$env:INITIAL_ADMIN_PASSWORD = "<كلمة مرور قوية وفريدة لا تقل عن 12 حرفًا>"
$env:INITIAL_ADMIN_NAME = "مدير النظام"
npm start
```

افتح `http://localhost:3000`. إذا كانت قاعدة المستخدمين موجودة بالفعل، فلا يلزم متغيرا المدير ولا يستبدل الخادم المستخدمين الموجودين. المتغيرات مطلوبة فقط عند إنشاء `delta_users.json` أول مرة.

لا تضع كلمة المرور في ملف متتبع في Git. لتشغيل دائم، استخدم مدير أسرار أو متغيرات بيئة محمية للمستخدم/الخدمة بدل إدخالها داخل سكربت محفوظ.

## بناء الواجهة وتشغيل التطبيق المبني

```powershell
npm run build
npm start
```

أو من مجلد الواجهة:

```powershell
cd frontend
npm install
npm run build
npm run preview
```

`npm run preview` يعرض build لغرض المعاينة فقط. لتشغيل النظام المتكامل، يفضّل أن يقدم Express مجلد `frontend/dist` حتى تتشارك الواجهة وAPI الأصل نفسه.

## وضع التطوير

نافذتا PowerShell من جذر المشروع:

```powershell
npm run dev
```

```powershell
npm run dev:ui
```

يفتح Vite عادةً `http://localhost:5173`، والوكيل يرسل `/api` و`/files` إلى `http://localhost:3000`.

## متغيرات البيئة

### الخادم

- `PORT`: منفذ HTTP؛ الافتراضي `3000`.
- `INITIAL_ADMIN_USERNAME`: اسم مستخدم المدير الأول.
- `INITIAL_ADMIN_PASSWORD`: كلمة مرور المدير الأول (12 حرفًا على الأقل).
- `INITIAL_ADMIN_NAME`: الاسم الظاهر؛ إن لم يُحدد يستخدم اسم الدخول.

الخادم يجزّئ كلمة المرور باستخدام `bcryptjs` بعامل 10 قبل كتابتها. إنشاء المدير يقتصر على مستخدم واحد عند غياب ملف `data/db/delta_users.json`.

### Vite/الواجهة

- `VITE_API_URL`: عنوان API؛ القيمة الفارغة أو غير المعرفة تستخدم نفس الأصل.
- `VITE_PUBLIC_BASE`: بادئة مسار build عند نشر الواجهة تحت مسار فرعي؛ الافتراضي `/`.

قيم `VITE_*` عامة وليست أسرارًا. تغيّر إعداداتها يتطلب إعادة بناء الواجهة.

## البيانات والنسخ الاحتياطية

تُخزن ملفات التطبيق النشطة ضمن `data/`:

- `data/db/delta_db.json`
- `data/db/delta_trash.json`
- `data/db/delta_users.json`
- `data/files/`

ينشئ Express المجلدات الناقصة. لا يحفظ Git هذا المجلد بسبب قواعد `.gitignore`.

يمكن تنزيل نسخة احتياطية من واجهة المدير/المحاسب؛ ينتج endpoint `/api/backup` أرشيف ZIP كاملًا لمجلد `data/`. الاستعادة عبر الواجهة تستخدم `/api/restore` وتستبدل البيانات الحالية. احفظ النسخ خارج مجلد المشروع، وجرّب الاستعادة على نسخة اختبارية قبل الاعتماد على أي نسخة مهمة.

## التحقق البرمجي

```powershell
cd frontend
npm run lint
npm run build
```

لا يوجد في الوقت الحالي أمر اختبار آلي فعلي للجذر أو الواجهة. تحقق يدويًا من تسجيل الدخول والقراءة والكتابة ورفع/تنزيل الملفات والنسخ والاستعادة في بيئة اختبار تحتوي بيانات غير حقيقية.

## النشر

المشروع مصمم حاليًا لخادم Node يحتفظ بتخزين `data/` محليًا. عند نشره:

1. استخدم مجلد تخزين دائمًا وقيود وصول للنظام على `data/`.
2. لا ترفع بيانات الإنتاج أو ملفات البيئة إلى Git.
3. لا تعرض الخدمة قبل إضافة مصادقة وتحقق صلاحيات على جميع مسارات API.
4. استخدم HTTPS ووكيلًا عكسيًا مضبوطًا، وقيّد أصول CORS، وحدد حدود حجم الملفات والطلبات.
5. راجع [SECURITY.md](SECURITY.md)، خصوصًا سلوك خدمة الترخيص الخارجي.
