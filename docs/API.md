# مرجع API

جميع المسارات معرفة في `index.js`. عند تشغيل Vite، يحوّل الوكيل `/api` و`/files` إلى `http://localhost:3000`. في البناء، يستخدم العميل نفس الأصل افتراضيًا أو `VITE_API_URL` إن تم ضبطه.

الطلبات JSON تستخدم `Content-Type: application/json`، باستثناء الرفع والاستعادة اللذين يستخدمان `multipart/form-data`. يستقبل Express أجسام JSON وURL-encoded حتى 50 MB.

> **تنبيه:** endpoints البيانات والملفات والنسخ الاحتياطي غير محمية بتحقق خادمي من المستخدم أو الدور في التنفيذ الحالي. لا تعرض الخادم على الإنترنت اعتمادًا على حماية صفحات React.

## تسجيل الدخول والجلسة

### `POST /api/login`

الطلب:

```json
{
  "username": "admin",
  "password": "your-password"
}
```

النجاح (`200`):

```json
{
  "success": true,
  "user": {
    "id": "admin",
    "username": "admin",
    "name": "مدير النظام",
    "role": "admin"
  }
}
```

الحقول الناقصة ترجع `400`؛ اسم المستخدم غير الموجود أو كلمة المرور الخاطئة ترجع `401`؛ خطأ الخادم يرجع `500`. تتم مقارنة كلمة المرور مع bcrypt hash.

### `GET /api/me`

يقرأ اسم المستخدم من الترويسة `x-username`:

```http
x-username: admin
```

يعيد `200` وبيانات المستخدم العامة عند العثور عليه، أو `401` إذا لم توجد الترويسة أو لم يطابق اسمًا محفوظًا. لا يستخدم التطبيق رمز جلسة أو token في هذا المسار.

## العملاء والمهملات

### `GET /api/data`

يعيد الملفين المحليين:

```json
{
  "clientsDB": [],
  "trashDB": []
}
```

إن لم يوجد ملف القائمة المقابل، يعيد مصفوفة فارغة. خطأ القراءة أو تحليل JSON يرجع `500`.

### `POST /api/data`

يكتب القائمتين بالكامل إلى `data/db/delta_db.json` و`data/db/delta_trash.json`:

```json
{
  "clientsDB": [],
  "trashDB": []
}
```

النجاح: `{"success": true}`. الطلب يستبدل محتوى الملفين، وليس تحديثًا جزئيًا لعميل واحد. لذلك قد تتعارض كتابات عدة مستخدمين إذا عدّلوا البيانات في الوقت نفسه.

## المرفقات

### `POST /api/upload`

نوع الطلب `multipart/form-data`، والحقول:

| الحقل | الوصف |
|---|---|
| `file` | الملف المرفق. |
| `clientId` | معرّف عميل موجود. |
| `fileType` | `receipts` لتسجيله كإيصال؛ أي قيمة أخرى تسجله ضمن `pdfs`. |

الامتدادات التي يقبلها مرشح Multer: `.pdf`, `.dwg`, `.jpg`, `.jpeg`, `.png`. تُخزن الملفات في `data/files/` باسم فريد مشتق من الوقت ورقم عشوائي، ثم يضاف مرجعها إلى العميل في قاعدة JSON.

النجاح: `{"success":true,"file":{"filename":"...","originalName":"...","date":"...","path":"/files/..."}}`. البيانات الناقصة ترجع `400`؛ العميل غير الموجود `404`؛ وأخطاء الرفع/الحفظ `500`.

### `POST /api/pdf-data`

الطلب:

```json
{ "filename": "stored-file.pdf" }
```

يعيد الملف بصيغة Base64 ونوع المحتوى:

```json
{
  "success": true,
  "data": "<base64>",
  "contentType": "application/pdf"
}
```

الملف غير الموجود يرجع `404`. الأنواع المحددة في الخادم: PDF، JPEG، PNG، وDWG؛ الافتراضي PDF.

### `GET /files/<filename>`

يقدم الملفات المحفوظة تحت `data/files/` باستخدام Express static.

### `POST /api/delete-pdf`

الطلب:

```json
{
  "clientId": "client-id",
  "filename": "stored-file.pdf",
  "type": "receipts"
}
```

يحذف مرجع الملف من `receipts` عندما يكون `type` مساويًا `receipts`، ومن `pdfs` في غير ذلك، ثم يحذف الملف الفعلي إن وجد. يعيد `{"success":true}` أو `404` عند غياب العميل.

## حذف العميل نهائيًا

### `POST /api/permanent-delete-client`

الطلب: `{"clientId":"client-id"}`. يبحث في `delta_trash.json`، ويحذف ملفات العميل ومعلوماته من المهملات. يعيد `{"success":true}`؛ العميل غير الموجود في المهملات يرجع `404`.

نقل العميل بين القائمة والمهملات يحدث عادة عبر `POST /api/data` من المتجر، وليس عبر endpoint منفصل.

## النسخ الاحتياطي والاستعادة

### `GET /api/backup`

ينشئ ZIP لمجلد `data/` كاملًا، بما فيه قواعد البيانات والمرفقات، ويعيده بنوع `application/zip` واسم `delta_backup_<timestamp>.zip`.

### `POST /api/restore`

يرسل ملف ZIP في حقل `backup` باستخدام `multipart/form-data`. يستخرج محتواه إلى `data/` مع استبدال الملفات الحالية. الملف الناقص يرجع `400`؛ نجاح الاستعادة يعيد `{"success":true,"message":"تمت الاستعادة بنجاح"}`.

**الاستعادة تستبدل بيانات التشغيل الحالية.** احتفظ بنسخة مستقلة قبل تنفيذها وتحقق من مصدر ملف ZIP. يجب ألا تكون هذه المسارات عامة قبل إضافة مصادقة وتحقق صلاحيات حقيقيين.

## تقديم الواجهة

ليست هذه endpoints تطبيقية للبيانات:

- عند وجود `frontend/dist`, يقدّم Express ملفات الواجهة المبنية ويعيد `index.html` للمسارات الأخرى.
- عند غياب build، يقدم ملفات `client/`.
- `/files` يقدم الملفات المرفوعة.

## رموز الحالة المعتادة

| الرمز | الاستخدام |
|---:|---|
| `200` | نجاح القراءة أو العملية. |
| `400` | مدخلات لازمة ناقصة أو ملف مطلوب غير مرفق. |
| `401` | فشل تسجيل الدخول أو التحقق من المستخدم في `/api/me`. |
| `404` | عميل أو ملف غير موجود. |
| `500` | خطأ أثناء قراءة/كتابة الملفات أو معالجة عملية الخادم. |
